# 访问控制

访问控制页把 PVE 的用户、用户组、角色、ACL 与 API 令牌收在一处，四个页签对应四类对象。

## 用户

用户标识必须带域后缀：

```text
root@pam           # Linux PAM 账户，密码由系统校验
automation@pve     # PVE 内置域，密码由 PVE 存储
ops@ldap           # 外部目录服务
```

- 新建 `@pve` 用户必须设置密码；`@pam` 用户则对应系统账户；
- 「启用」开关对应 `enable` 字段，停用后无法登录但配置保留；
- 编辑时可留空密码表示不修改。

## 用户组

用户组本身不带权限，作用是让 ACL 授权一次作用于一批用户。组内成员通过用户的 `groups` 字段关联，在用户编辑弹窗里勾选即可。

## 角色与权限

角色是权限集合，PVE 内置了 `PVEAdmin`、`PVEAuditor`、`PVEVMAdmin` 等。页签内只读展示每个角色包含的权限项（`VM.Allocate`、`Datastore.Audit` 之类）。

**内置角色不可修改**，如需裁剪请新建自定义角色并在 PVE 端配置。

## 权限（ACL）

ACL 把角色授给某个对象（用户 / 组 / 令牌），作用在某个路径上：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| 路径 | `/`、`/vms/204`、`/storage/nas` | 以 `/` 开头 |
| 对象 | `ops`（组）、`automation@pve`（用户） | 组以 `@` 前缀显示在表单里 |
| 角色 | `PVEAdmin` | 决定能做什么 |
| 传播 | 是 / 否 | 是否继承到子路径 |

授权粒度参考：

```text
/                PVEAdmin      给运维组全量权限
/vms/204         PVEAuditor   让监控账号只读该虚拟机
/storage/nas     PVEDatastoreAdmin  允许管理某个存储
```

## API 令牌

令牌用于脚本与自动化，不需要保存用户密码。在用户行点「令牌」创建：

- **令牌标识**：小写字母开头，可含数字、点与短横线；
- **权限分离**：开启后令牌**不继承**用户权限，必须单独为其配置 ACL；关闭则继承用户全部权限。

创建成功后密钥（Secret）**只显示一次**，关闭弹窗后无法再次查看。完整令牌标识形如：

```text
automation@pve!deploy
```

调用 API 时把它和密钥拼成 `PVEAPIToken=automation@pve!deploy=<secret>` 放在 `Authorization` 头里。

::: tip 最小权限
生产环境建议给令牌开启「权限分离」，再单独授予所需路径的角色，避免把管理员权限扩散到 CI 系统。
:::
