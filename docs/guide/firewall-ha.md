# 防火墙与高可用

两页分别对应 PVE 的防火墙策略与 HA 资源管理，都在**集群运维**分组下。

## 防火墙

PVE 防火墙分三层，规则逐层叠加生效：

```text
集群级规则 → 节点级规则 → 虚拟机级规则
```

页面顶部的「集群 / 节点 / 虚拟机」切换器决定当前编辑哪一层，切换后规则表与启用状态都会重新读取。

### 规则字段

| 字段 | 说明 | 留空 |
| --- | --- | --- |
| 方向 | 入站 / 出站 | 必选 |
| 动作 | `ACCEPT` / `DROP` / `REJECT` | 必选 |
| 协议 | `tcp` / `udp` / `icmp` / `any` 等 | 匹配任意 |
| 源 / 目标 | IP 或 CIDR，如 `10.0.0.0/24` | 匹配任意 |
| 目标端口 | `22`、`80,443` 或 `1000:2000` | 匹配任意 |
| 网络接口 | 如 `vmbr0` | 匹配任意 |
| 日志级别 | `nolog` 到 `debug` | 不记录 |

规则**按序号从上到下匹配**，命中即停止。新规则追加到末尾；改优先级需要删除后重建。

### 启用与策略

右上角的开关切换该层的 `enable` 选项。停用防火墙时规则表依然保留，重新启用后立即生效。

入站 / 出站默认策略（`DROP` / `ACCEPT`）在 PVE 侧维护，本页只读展示。若发现规则正确但流量仍被拒，先确认策略值。

::: warning 集群级规则影响面最大
在集群层误加一条 `DROP` 规则可能把自己锁在外面。建议先在虚拟机级验证，再逐层提升。
:::

## 高可用

### 把虚拟机加入 HA

顶部下拉列出尚未托管的虚拟机（`vm:204` / `ct:118` 形式），选择后点「加入」。加入后该虚拟机会由 HA 管理器接管：

- 所在节点宕机时自动在其它节点重启；
- 受 `max_restart` 与 `max_relocate` 限制，避免无限重启风暴。

### 状态控制

每行的「启动 / 停止」是对 HA 资源下发 `request_state`，不是直接开关电源——最终由 HA 管理器在合适的节点执行。

### 节点组

节点组定义 HA 资源的候选节点与优先级：

```text
pve1:1,pve2:2      # pve1 优先，pve2 次之
```

- **受限组**：资源只能跑在组内节点上，节点全挂时不会迁到组外；
- **不自动回切**：故障节点恢复后，资源留在当前节点运行，不回迁。

删除节点组前，先把引用它的 HA 资源移出，否则 PVE 会拒绝删除。
