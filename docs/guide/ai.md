# AI 运维助手

AI 助手是侧边栏「智能助手 → AI 助手」里的对话式运维入口。用自然语言查询集群，也可以让它在权限允许的范围内执行电源操作、创建快照。

## 支持的模型接口

| 服务商 | 默认 Base URL | 默认模型 | API Key |
| --- | --- | --- | --- |
| OpenAI / GPT | `https://api.openai.com/v1` | `gpt-4o-mini` | 必填 |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 必填 |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` | 通常不需要 |
| 自定义 | 自建网关地址 | 自填 | 按网关要求 |

接口统一走 OpenAI 兼容的 `POST /chat/completions`，并要求模型支持 **function calling / tools**。
Ollama 建议使用 `qwen2.5`、`llama3.1` 等支持工具调用的模型。

## 配置

「首选项 → AI 助手」：

1. 选择服务商，Base URL 与默认模型会自动填好；
2. 填写模型名（例如 `deepseek-chat`、`gpt-4o-mini`、`qwen2.5:7b`）；
3. 填写 API Key，点「保存 Key」；
4. 选权限边界；
5. 点「测试连接」确认地址、模型、Key 都可用。

API Key 用系统 `safeStorage`（Windows DPAPI）加密保存在主进程，**不会回传到渲染进程**，也不会出现在对话上下文里。

## 权限边界

| 模式 | 查询工具 | 变更工具 |
| --- | --- | --- |
| 只读 | 自动执行 | 直接拒绝，不产生审批 |
| 每次确认（默认） | 自动执行 | 生成确认卡片，点「允许执行」后才调用 PVE API |
| 完全授权 | 自动执行 | 直接执行（红色高风险操作也不再询问） |

变更工具只有两个：

- **虚拟机电源操作**：启动、ACPI 关机、强制停止、重启、挂起、恢复；
- **创建快照**：名称 + 可选描述，不包含内存状态。

不提供删除虚拟机、修改磁盘/网络/防火墙/用户、执行 Shell 命令等能力。
即使 AI 被诱导要求这些操作，主进程的工具白名单也会拒绝。

## 工具与审批流程

只读工具：

- `get_cluster_overview`：集群、节点、虚拟机、存储、运行任务概览；
- `get_vm_detail`：按 VMID 查询运行状态、配置摘要、磁盘、快照；
- `list_tasks`：最近任务，可只看失败；
- `get_task_log`：读取 UPID 的日志（最多 80 行）。

变更工具在「每次确认」模式下会先返回审批卡片，显示工具名、参数和风险级别。
卡片里的「允许执行 / 拒绝」是唯一能触发变更的入口；用户拒绝时，AI 会收到“用户拒绝”的工具结果并继续解释。

权限切换到只读后，之前未处理的审批会立即作废。

## 安全与隐私

- 工具只通过现有 `PveManager` 调用 PVE API，使用当前登录用户的 PVE 权限；PVE RBAC 仍然是最后一道边界；
- AI 不接触 PVE 密码、API Key、票据、Cookie、SSH 凭据；
- 发送给外部模型的内容是对话文本与工具返回的集群摘要；使用云端服务前请确认数据合规；
- 对话按 PVE 地址 + 账号隔离，切换账号会清空对话缓存；
- 系统提示明确要求模型忽略绕过权限、调用未提供工具或泄露系统信息的指令。

## 使用示例

```text
列出所有运行中的虚拟机，按节点分组
最近有哪些失败的任务？帮我看看原因
把 VM 204 启动起来，然后确认状态
给 VM 204 创建一个名为 before-upgrade 的快照
```

## 限制

- 模型必须支持 function calling；不支持时接口会报错；
- 工具结果会截断到 8k 字符，避免上下文爆炸；
- 单轮最多 6 个工具调用轮次；
- 助手不做长任务轮询，创建快照/电源操作后需要再问一次“现在状态如何”；
- AI 不会自动安装 Guest Agent、SSH 或修改 PVE 配置。
